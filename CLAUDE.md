## Audio playback gotchas (`src/audio/ChunkPlayer.ts`)

- Chunk timing (API v2.9+): the temperature sets the tempo, so a 30 s chunk holds 8-13 months (more in fast styles, e.g. rock'n'roll ~19). `computeChunkTiming` uses `response.duration_s` (capped by the decoded buffer) and the position inside a chunk is piecewise linear over `bar_starts_s` (month i spans `bar_starts_s[i]` to `[i+1]`, the last one to the duration). Never assume one bar = one month = 3 s: that is only the fallback (`SECONDS_PER_MONTH`) for old backends that send neither field. The last chunk runs up to the month after the enabled tracks' last data, capped at the decoded audio.
- Chunk N+1 is scheduled at chunkStart + `duration_s` (the ~1.7 s reverb tail overlaps on purpose), prefetched at 20%; `next_time_period: null` = end. Requests are aborted on seek / zone / track / style change (`PlayerParams.genre`, compared in `paramsChanged`).
- The AudioContext must be created on the first `play()` (browser autoplay policy) — never at module load or mount.
- iOS mutes Web Audio under the silent/ringer switch ("ambient" session): `play()` must, synchronously in the gesture, request `navigator.audioSession.type = 'playback'` or start the silent `<audio>` fallback (`src/audio/iosAudioUnlock.ts`). An `'interrupted'` context (call, Siri, lock screen) pauses the player.
- There is no per-track volume: the backend returns one mixed file.
- API types in `src/services/sonificationApi.ts` mirror `../sonification/backend/FRONTEND_API.md`; update them together.
- Music style: `StyleSelector` (`components/controls`, "Music style" `<select>` fed by `GET /api/genres`; `RECOMMENDED_STYLES` (orchestra, realistic) in a "Recommended" `<optgroup>`, the rest in "Just for fun", with the reason in the label's (i) InfoTooltip, also in the select's aria-describedby; description as aria-describedby hint, polite "Music style: Funk" announcement) sits above `TrackPanel` in both modes. `hooks/useMusicStyle.ts` holds the choice (localStorage `earth-jukebox-music-style`, validated against the list; undefined = no `genre` sent, e.g. a backend without `/api/genres`). It goes to `useSonification` -> `ChunkPlayer.setParams({genre})`, to `useVinylSonification` -> groove / zone-data requests, and to `useInstruments(genre)` (`?genre=`, so track rows show that style's instruments; the list stays on screen while it reloads). `usePlayerShortcuts` ignores `select`, so keys work inside the selector.
- Vinyl mode (`src/services/vinylApi.ts`, `hooks/useVinylSonification.ts`) plays `POST /api/zones/groove` (API v2.10, optional `genre`): each 30 s chunk sends `groovePath(center, k)` (10 bars of a fixed 3 s; `points_per_bar` 4/2/1 so points stay >= 2 degrees apart, <= 80 points); `stops[i]` plays from `i x stop_seconds` and drives the data trail on the globe (`null` = no data, no dot). It reuses ChunkPlayer: groove k is encoded as the synthetic period `2000-01 + 10k months` (never sent to the backend) and every synthetic chunk claims `duration_s: 30` with ten 3 s `bar_starts_s`. The vinyl position lives in its own position store too.
- Vinyl travel modes (`useVinylSettings`: `travel` space|time|both, `step` month|year for both, same storage key; changing travel, step, genre, centre or month lifts the needle back to the rim). Space: one date, the needle crosses places. Both: groove k is `groovePath(center, k)` at `addMonths(timePeriod, k x step)`, ending when the next date passes the enabled tracks' range end. Time: one place; `makeVinylChunkFetcher` calls `fetchZoneData` on `discPoints(center)` (a few points in a `GROOVE_RADIUS_DEG` disc) starting at the real period P_k, and keeps a k -> period map (P_(k+1) = `next_time_period`; an unheard groove is estimated as `timePeriod + 10k` months; `next_time_period: null` ends the side). The real months and their `bar_starts_s` travel in `VinylChunkMeta` (`travel`, `periods`, `barStarts`); `periodAt` gives the date under the needle, shown in the player bar, globe caption, sr-only table (date column) and announcements. In time mode the globe has no moving trail, only one centre spot coloured by the groove's value (`timeSpot`), and no reduced-motion needle marker. zone-data only returns the value at the chunk's first month, so that spot changes once per groove, not per month.
- Month travel (Time travel mode, "Months" select `components/player/MonthTravelControl.tsx`): `useSonification` keeps `monthFilter` (1-12 or null; localStorage `earth-jukebox-month-travel`) and passes it as `PlayerParams.month`. ChunkPlayer then snaps every period to that month (`withMonth` / `monthOccurrence`) and sends `step: "year"` (API v2.12, `FRONTEND_API.md` "the same month, year after year"): one bar = one year, so the position still is a fractional year but crosses a whole year per bar (`monthsPerBar = 12`). Labels must use `snapToMonth(position, month)` (Timeline, DatePicker, chart legend, `derivePlayback().currentYear`, globe `frameMonthKey`), never the raw playhead. A response without the `step: "year"` echo (backend < 2.12 ignores the field), or a 422, fails with `yearStepUnsupported` (no retry; App opens the graph once). Night lights (yearly) plays fine with `step: "year"` on the deployed backend (its prepared data is one map per month), so every enabled track is sent. `SeriesChart` `month` prop draws that month of each year from `/zones/series` (`monthValues`, `buildMonthPaths`).

## Visual identity

- Palette comes from the logo (`design/logo-source.png`; web sizes in `public/`: favicon, icons, `logo-96/320.{png,webp}`, `og-image.png`). Tokens in `src/styles/variables.css`: primary = label yellow `#f5d078`, secondary = ocean blue `#4a6fc7` (graphics only; `--color-secondary-text` for blue text), land green `--color-land`, deep ocean-blue surfaces (`#071327` background → `#1c3663` active, hue of the logo's ocean).
- Anything filled with `--color-primary` uses `--color-on-primary` (navy) for text/icons — never white.
- No borders on containers, rows or buttons: separate with surface tone (background → surface → elevated/active), spacing and headings. Borders stay only on form controls (`--color-control-border`, >= 3:1), data marks and in high-contrast mode. No gradient text, glows, blur, coloured left stripes or emoji icons (inline SVG, `stroke="currentColor"`, `aria-hidden`).
- Data colours (`src/data/trackColors.ts`) are separate from the brand. Lightning `#ffe815` is almost the label yellow, so selected/active states near track dots use neutral `--color-surface-active` plus a check/weight, never yellow.

## Accessibility component rules (WCAG 2.1 AA is mandatory)

- **Forms**: every `<input>` has an associated `<label>` (`htmlFor`/`id` or wrap).
- **Buttons**: semantic `<button>`; `aria-label` when icon-only.
- **Dialogs**: close on Escape and give focus back to the trigger. A true modal (`aria-modal="true"`) also traps focus; the `DatePicker` popover is a non-modal `role="dialog"` (no `aria-modal`, no focus trap): it closes on Escape, outside click or Tab out, and focus returns to its trigger. The player shortcuts (`usePlayerShortcuts.ts`) ignore any open `role="dialog"` / `aria-modal`. Known issue: the Escape handler in `GlobeView.tsx` only skips when an `aria-modal` is open, so Escape in the date picker also returns to zone selection.
- **Charts/visualizations**: include a hidden `<table>` with the full data.
- **Audio/sonification**: text alternatives are the `sr-only` data tables and summaries (`SeriesChart.tsx` table + `graph.summary`, `GlobeView.tsx` table) plus `aria-live` announcements.
- **Dynamic content**: `aria-live` regions for status updates.
- Player controls must keep: Space (play/pause), arrows (previous/next), Home/End (first/last), M (mute), handled globally in `src/hooks/usePlayerShortcuts.ts`; Escape returns to zone selection (`GlobeView.tsx`). On the timeline slider: arrows 2%, Shift+arrows 1 month (1 year in month travel), PageUp/PageDown 1 year (`Timeline.tsx`). There is no `?` shortcut.
- Playback position (`src/hooks/usePlaybackPosition.ts`) lives in an external store, not React state: ChunkPlayer reports it ~10x/s and only the timeline, date picker and chart re-render. Do not lift it into `App` state.
- In `npm run dev`, axe-core logs violations to the browser console — check it after UI changes.
